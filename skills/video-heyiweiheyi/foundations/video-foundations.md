# 视频底层通用制作规范（Silent Foundations）

> **生效方式**：本文档中的所有规范均为**底层静默底座**，不出现在交互向导的模板或转场菜单中，但在策划、生成、剪辑、合成或精修任意视频（含公式化模板、转场以及 AI 自主设计片段）时全程强制生效。

---

## 1. 编辑保护、版本留痕与文件锁处理

1. **保护用户已有工程与成片**：
   - 修改已有成片、素材目录或剪辑工程前，先核查目标文件 `mtime`；若文件已交付或经过用户手动微调，先备份至工作临时目录（如 `scratch/` 或 `tmp/`），**严禁直接覆盖用户原文件**。
   - 迭代输出默认采用清晰版本号后缀（如 `_v2.mp4`、`_精修版.mp4`），仅在用户明确要求覆盖且无进程锁定时原位替换。
2. **Windows 文件锁（`PermissionError`）处理**：
   - 若成片正被播放器、剪映、Premiere 或资源管理器预览占用而写入失败，绝不强杀用户进程；先写入新文件名验证通过，再明确提示用户关闭占用程序。
3. **无损保留原始素材**：
   - 所有缩放、裁剪、调色、转码和降噪都在中间临时目录生成副本，绝不就地改写用户提供的原始照片、视频或音频文件。

## 2. 画幅规格、帧率与平台安全区规范

### 2.1 标准分辨率与帧率
| 画幅类型 | 标准分辨率 | 适用场景 | 推荐帧率 |
| :--- | :---: | :--- | :---: |
| **16:9 横屏** | `1920 × 1080`（4K：`3840 × 2160`） | B站 / YouTube / 汇报演示 / 宣传片 | `30 fps`（快闪/高动态推荐 `60 fps`） |
| **9:16 竖屏** | `1080 × 1920`（4K：`2160 × 3840`） | 抖音 / 视频号 / 小红书 / Reels / Shorts | `30 fps` 或 `60 fps` |
| **1:1 方形** | `1080 × 1080` | 信息流卡片 / 社交图文视频 | `30 fps` |

- **全片帧率与尺寸硬统一**：同一条视频内所有片段在总装前必须统一到**完全一致的宽高、帧率（CFR 恒定帧率，严禁 VFR 可变帧率引发音画漂移）和 SAR `1:1`**。
- **任意比例图片/视频适配准则**：默认采用 **Center Cover（等比裁切填满画布，避免黑边与拉伸变形）**；若素材含关键人像或文字不可裁切，则改用 **模糊压暗同源背景 + 居中完整主体（Blurred Pillar/Letterbox）**，严禁生硬拉伸变形。

### 2.2 平台安全区（防字幕与标题被 UI 遮挡）
- **16:9 横屏安全区（`1920 × 1080`）**：
  - 四周基础标题安全边距：**左右各 `96 px`（5%），顶部 `54 px`（5%），底部 `108 px`（10%，避开播放器进度条）**。
  - 标准单行/双行字幕基线建议位于 `y = 860 ~ 972 px`（距底 `108 ~ 220 px`）。
- **9:16 竖屏安全区（`1080 × 1920`，抖音 / 视频号 / 小红书通用）**：
  - **顶部避让**：`0 ~ 250 px`（约顶部 13%，状态栏与顶导航）。
  - **底部避让**：`1480 ~ 1920 px`（约底部 23%，昵称、文案描述、话题与底栏）。
  - **右侧避让**：`x = 920 ~ 1080 px`（右侧约 15%，头像、点赞、评论、收藏、转发图标列）。
  - **左侧避让**：`0 ~ 60 px`（约 5.5%）。
  - **竖屏字幕黄金区**：居中偏下 **`y = 1260 ~ 1440 px`**（字号建议 `56–68 px`，每行不超过 `12–15` 个汉字，强制自动折行不触碰右侧图标区）。

### 2.3 字幕与排版克制美学
- **字体优先级**：Windows 优先 `微软雅黑 Bold`（`msyhbd.ttc`）或 `思源黑体`（`Noto Sans CJK SC` / `Source Han Sans`）；跨平台缺失中文字体时自动探测系统可用 CJK 字体，绝不渲染“豆腐块”乱码。
- **高对比可读性**：浅/杂画面上的字幕必须加 **`2–3 px` 深色描边 + 轻微半透明暗底阴影**（或 40%–55% 不透明度极简暗胶囊条），严禁五彩霓虹渐变字、浮夸抖动特效或无逻辑 emoji 堆砌。

## 3. 编码兼容与多引擎分段总装契约

### 3.1 通用成片编码硬标准（确保微信 / iOS / Android / 浏览器 100% 可播）
```text
容器格式 : MP4 (.mp4)
视频编码 : H.264 (libx264), Profile high/main, Level 4.1+
像素格式 : yuv420p（严禁输出 yuv444p / 10-bit 导致手机黑屏无法播放）
码率控制 : CRF 18–20（高画质交付）, preset medium/slow, CFR 恒定帧率
封装优化 : -movflags +faststart（moov 原子前置，支持边下边播）
音频编码 : AAC-LC, 192 kbps, 48000 Hz, Stereo (2 ch)
```

### 3.2 FFmpeg 跨环境自动发现规范
所有自动化脚本优先调用系统 `PATH` 中的 `ffmpeg` / `ffprobe`；若 Windows/沙盒未单独配置环境变量，自动通过 `imageio_ffmpeg.get_ffmpeg_exe()` 回退到 Python 内置的 `ffmpeg` 二进制（详见 [`./scripts/ffmpeg_utils.py`](./scripts/ffmpeg_utils.py)）。

### 3.3 多引擎分段总装契约（Decoupled Engines → Unified FFmpeg Bus）
- 不同段落模板可自由选择最擅长的引擎：
  - **像素合成 / 关键帧动效 / 跨平台零 Node 依赖**：`python-pil-ffmpeg`（`Pillow` + `numpy` 逐帧管道直推 `ffmpeg` stdin，比 MoviePy 更稳更快）。
  - **动态排版 / UI 卡片 / 现代片头片尾**：`remotion`（无 Node 环境时自动回退至 `python-pil-ffmpeg`）。
  - **数学公式 / 几何原理演绎**：`manim`。
  - **实拍剪辑 / 滤镜调色 / 转场 / 混音封装**：`ffmpeg`。
- **标准化中间片协议**：各段落独立产出同宽、同高、同帧率、`yuv420p`、`48kHz` 双声道（无声段自动补静音轨 `anullsrc`）的标准中间 `.mp4`，并按所选转场时长预留重叠帧（Handles，通常 `0.5s–1.5s`），最终交由 [`./scripts/assemble_timeline.py`](./scripts/assemble_timeline.py) 统一拼接、转场与响度总装。

### 3.4 无实拍视频的 Ken Burns 动态镜头兜底
当段落需要视频画面、但仅有静态图片或 AI 生成图时，严禁直接静态僵硬定格数秒；统一通过 [`./scripts/ffmpeg_utils.py`](./scripts/ffmpeg_utils.py) 中的 `image_to_ken_burns()` 施加缓慢平滑的推拉/微平移（例如 `1.00× → 1.08×` 缓动推镜），赋予静态画面电影呼吸感。

## 4. 音频工程规范：Audio-First、响度归一化与人声闪避

1. **Audio-First（音频驱动时间轴）**：
   - 在「配音旁白模式」下，必须先生成或探针测量每段旁白音频的精确时长（精确到 `0.01s`），再以「旁白时长 + 前后呼吸留白 `0.25s–0.40s`」反推对应镜头时长与字幕时间戳（SRT/ASS），彻底杜绝“画面切走了话还没说完”。
   - 在「纯 BGM 卡点模式」下，优先按 BGM 节奏/鼓点间隔决定快闪或切镜步长（如 `120 BPM` 半拍 `0.25s` / 一拍 `0.50s`，或通用走马灯 `0.15s` 半步交错）。
2. **响度归一化标准（EBU R128）**：
   - 互联网平台成片综合响度目标：**`-14 LUFS`（短视频/B站/YouTube）** 或 **`-16 LUFS`（播客/口播解说）**，允许误差 `±1.5 LU`，真峰值上限 **`True Peak <= -1.0 dBTP`**（严禁削波爆音）。
3. **人声优先与 BGM 闪避（Sidechain Ducking）**：
   - 有旁白人声时，BGM 必须压低 **`-14 dB ~ -18 dB`**（或通过 FFmpeg `sidechaincompress` 在人声出现时自动平滑闪避，人声停顿 `0.3s` 后柔和回升）。
   - BGM 开头加 `0.5s–1.0s` 音频淡入（`afade=t=in`），片尾加 `1.0s–2.0s` 音频淡出（`afade=t=out`），绝不硬切断音。
4. **音画同步**：
   - 成片视频流时长与音频流时长差必须 **`< 0.05s`**（除刻意结尾留黑静默外），杜绝首尾拖尾黑帧或音画逐渐漂移。

## 5. 必做双维自动化验收闭环（严禁盲交成片）

每次交付最终 `.mp4` 前，必须依次运行以下两个内置验收脚本：

### 5.1 硬指标技术体检（`probe_video.py`）
```bash
python skills/video-heyiweiheyi/foundations/scripts/probe_video.py \
  --input path/to/final.mp4 \
  --expected-aspect 16:9
```
自动检查并输出 JSON/摘要报告：
- 视频编码是否为 `h264`、像素格式是否为 `yuv420p`、分辨率与帧率是否合规；
- MP4 头部是否已做 `faststart`（`moov` 位于 `mdat` 之前）；
- 音视频流时长差是否 `< 0.05s`；
- 音频综合响度（`LUFS`）与峰值（`dBTP` / `max_volume`）是否过小或爆音；
- 是否存在意外的首尾长黑帧（`blackdetect`）或异常死静音（`silencedetect`）。

### 5.2 关键帧联系表视觉目检（`extract_keyframes.py`）
```bash
python skills/video-heyiweiheyi/foundations/scripts/extract_keyframes.py \
  --input path/to/final.mp4 \
  --output path/to/contact_sheet.png \
  --safe-zone auto \
  --count 12
```
自动按时间轴均匀 + 关键节点（入场、转场区、中段、片尾）抽帧，拼成带**精确时间戳**和 **16:9 / 9:16 平台安全区参考虚线框** 的 `contact_sheet.png`。Agent 必须实际打开并目检该联系表图片，确认：
- 无黑边、拉伸畸变、绿屏或花屏帧；
- 字幕与主标题完整落在安全区内，未被平台底部/右侧 UI 遮挡，无越界裁切；
- 转场叠加与叠影透明度过渡自然，片尾干净收束。
